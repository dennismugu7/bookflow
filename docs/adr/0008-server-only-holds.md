# ADR 0008: Holds are created only by our server

**Status:** accepted (2026-10-03). **Supersedes:** the per-IP limit design in Phase 1b.

## Context
`create_hold` (Phase 1b) limited each visitor to 10 holds per hour, keyed on the first `x-forwarded-for` entry that PostgREST passes to the database. Visitors can set that header themselves, so a bot could rotate fake addresses and hold every slot in a salon for 10 minutes at a time, for free. Claude Code spotted this during Phase 1b.

## Decision
- `create_hold` is executable only by `service_role` and takes the client IP as a parameter.
- The only caller is a Next.js route on Vercel. It (1) verifies a Cloudflare Turnstile token, (2) reads the IP from Vercel's own `x-real-ip` / `x-vercel-forwarded-for` headers and never from `x-forwarded-for`, and (3) calls the database with the secret key, which lives only in Vercel's server environment.
- The hold token is generated by the server and kept in an `httpOnly` cookie, so page scripts never see it.

## Consequences
- Bots must pass Turnstile for every hold, and the rate limit uses an address they can't forge.
- One more secret (`SUPABASE_SECRET_KEY`) and a Turnstile key pair to manage. Both are free.
- Availability stays public and is read directly from the browser; only the write path moved.
- Acceptance test 07 was revised by the lead to call `create_hold` as `service_role` and to prove that `anon` and `authenticated` can no longer call it.
